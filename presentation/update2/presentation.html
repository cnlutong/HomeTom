Architecture Standard Page 2/9

Asynchronous I/O Protocol

SYNCHRONOUS

Property Access

Reading cached attributes remains synchronous for high-speed access.

Hardware synchronization occurs concurrently across multiple devices.
ASYNC/AWAIT

Device Control

All state-changing commands are executed asynchronously to prevent thread blocking.

ASYNC/AWAIT

State Polling

Periodic state synchronization is handled via non-blocking event loops.

Standardized patterns for non-blocking device control and state management.

Light Implementation

class Light(Actuator):

    async def turn_on(self):
        await self.adapter.send('ON')
        self._state = "on"

    async def set_brightness(self, val):
        if 0 <= val <= 255:
            await self.adapter.set_level(val)
            self._brightness = val

Domain Layer Architecture Page 5/9

The domain layer is the pure core of the system, adhering to standard DDD patterns. It has zero dependencies on infrastructure or frameworks.

Core Principles

  • Aggregates: Transaction boundaries.
  • Value Objects: Immutable characteristics.
  • Side-Effects: Handled via Domain Events.

Scene Domain: Logic & Patterns Page 8/9

A SceneAggregate uses a robust Trigger-Condition-Action (T-C-A) model, backed by proven Design Patterns for flexibility.

Triggers

Events that initiate the evaluation process.

  • Manual Invocation
  • Cron Schedule
  • Device Event (e.g., Sensor Motion)

Conditions

Boolean predicates evaluated against current state.

Specification Pattern Allows composing complex logic (AND/OR/NOT) dynamically without hardcoding.

Actions

Side effects executed if conditions pass.

Command Pattern Encapsulates requests as objects (JSON), enabling queuing, logging, and undo operations.
T-C-A Pattern implementation enhanced with DDD best practices.

Execution Domain Page 9/9

Runtime Context

The ExecutionAggregate does not just run code; it records a forensic audit trail of why and how automation occurred.

  • Traceability: Links execution back to the specific Trigger Source (User ID or Event ID).
  • Snapshot: Captures `ExecutionContext` variables at the moment of start.

Reliability Engineering

Retry Policy Strategy

Configurable per execution context to handle transient failures.

  • MAX_RETRIES = 3
  • BACKOFF_FACTOR = 1.5
  • INTERVAL = 500ms

Events: ExecutionStarted → ExecutionSucceeded | ExecutionFailed

Ensuring observability and resilience in automation logic.
